# BL-290 — `mix compile` fails on Windows: `copy_binary/3` looks for the nonsuffixed worker binary

**Date filed:** 2026-10-06 · **Type:** defect — root cause named ·
**Row:** BL-290 (open, `docs/backlog-2026-06.md` §Harness) · **Design:**
`docs/aetheris/backlog/bl-290-worker-exe-copy.md` · **Citations:** `H` =
harness `aetheris` at `77cb0ab`.

---

## The finding

On Windows, `mix compile` of the harness fails in the copy step:

- `lib/mix/tasks/compile/aetheris_worker.ex:9@H` — `@worker_binary
  "aetheris_worker"` (likewise `@exec_server_binary
  "aetheris_exec_server"` at `:10`).
- `copy_binary/3` (`:43-49@H`) — `File.copy!(Path.join(release_dir,
  name), Path.join(out_dir, name))` with `release_dir =
  "native/target/release"`, `out_dir = "priv/worker"` (`/priv/exec_server`).

Cargo emits **`aetheris_worker.exe`** (and `aetheris_exec_server.exe`)
into `native/target/release/` on Windows; the copy looks for
`aetheris_worker` (no suffix), so `File.copy!/2` raises **`File.CopyError`**,
`run/1` returns `{:error, []}`, and `mix compile` fails on Windows — a
diagnosed root cause: **the mix task assumes Unix ELF output naming**.

The same nonsuffixed name is also the consumed path:
`lib/aetheris/worker/client.ex:241@H` resolves the worker as
`priv/worker/aetheris_worker`, and `lib/aetheris/cli/commands/doctor.ex:37@H`
checks the same path — so the repair must decide the suffix at both ends
(the copy out of `native/target/release/` and the paths the runtime
consumes), or copy both names. That consequence is named in the design
brief, not fixed here.

## Reproduction

Live-first on Windows: `mix compile` after a clean `native/` raise. The
static proof is the tracked code: the nonsuffixed literals at `:9-10@H`
and the bare `Path.join` copy at `:43-49@H` — on Windows, cargo's
Windows output naming is standard, so the copy target cannot exist.
`git grep -n "exe" lib/mix/tasks/compile/aetheris_worker.ex lib/aetheris/worker/client.ex lib/aetheris/cli/commands/doctor.ex`
returns **zero hits at `H`** — no Windows branch exists anywhere in the
chain.
