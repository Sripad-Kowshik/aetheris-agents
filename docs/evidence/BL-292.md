# BL-292 — run_command refuses bash, so a gate agent cannot run an existing shell script

**Date filed:** 2026-10-28 · **Type:** missing capability — `bash` as a
permitted `run_command` name · **Row:** BL-292 (open,
`docs/backlog-2026-06.md` §Harness) · **Design:**
`docs/aetheris/backlog/bl-292.md` · **Citations:** `H` = harness
`aetheris` at `dcc59bb`.

---

## The finding

The exec server's `run_command` cannot execute a shell script, because
the command name is matched against a hardcoded allowlist that does not
carry `bash`:

- `native/aetheris_exec_server/src/runner.rs:33-50@H` —
  `PERMITTED_COMMANDS`, the 16-name const (`mix`, `cargo`, `git`,
  `elixir`, `python3`, `python`, `node`, `npm`, `rg`, `find`, `cat`,
  `ls`, `echo`, `wkhtmltopdf`, `gs`, `f2-scanner`).
- `runner.rs:56-64@H` — `is_permitted/1` matches only the command's
  final path component against that const.

A name not in the const is refused at dispatch:
`native/aetheris_exec_server/src/main.rs:444-459@H` —
`handle_run_command` returns `isError: true` with
`stderr: "command not permitted: {command}"` and `exit_code: -1` for any
command whose basename is absent from the const.

The refusal is pinned by a unit test:
`runner.rs:234-239@H` — `non_permitted_command_is_blocked` asserts
`!is_permitted("bash")` at `:238@H` (alongside `curl` and `wget`). So
`bash` is refused **deliberately** — flipping it is a tracked change,
not an accident to sneak past a test.

Consequence: an agent that must run an **existing shell script** (a
repo's `scripts/*.sh` gate, for instance, with a script path and fixed
arguments) has no permitted way to invoke it — every argv must start
with one of the 16 names. The agent is forced to inline the script's
steps as ad-hoc permitted-binary invocations instead of running the
artifact as written, which is exactly the substitution the script
exists to prevent.

## Reproduction

No live run required — the refusal is static and unit-pinned:

- `grep -n '"bash"' native/aetheris_exec_server/src/runner.rs` → the one
  hit at `:238@H` is the negative assertion; `bash` appears nowhere in
  `PERMITTED_COMMANDS` (`:33-50@H`).
- `cargo test -p aetheris_exec_server non_permitted_command_is_blocked`
  at `H` passes with `bash` refused.

## Closure record — 2026-10-28

**T1 landed in the harness: bash joins the permitted names.** The
harness commit, cited: `7476cfc` ("BL-292 T1: bash joins the
run_command permitted names").

- **Arm 1 — bash accepted.** `PERMITTED_COMMANDS`
  (`runner.rs:33-51@H` at the ticket) gains `"bash"` alone, placed
  after `"echo"`; the pinned refusal at `runner.rs:238` is flipped in
  the same commit — `non_permitted_command_is_blocked` drops the
  `!is_permitted("bash")` line and `permitted_basename_is_allowed`
  gains the positive `is_permitted("bash")` pin. `curl` and `wget`
  stay refused; the path-traversal refusals pass untouched.
- **Arm 2 — a script-path call returns the exit code.** The dispatch
  path needed no edit: the gate lives on the name and the args vector
  passes through verbatim, so `["<script>", …fixed args…]` rides the
  same `run()` that the commit's new runtime pin drives —
  `run_bash_returns_the_existing_run_result` dispatches a real bash
  call and asserts the ordinary `RunResult` (exit code and stdout).

C4 held in the same commit: nothing else admitted, the refusal path
(`main.rs:444-459`) untouched. The harness commit also records one
deliberate side effect (`priv/exec_server/aetheris_exec_server`
rebuilt by the standard compile pipeline, which is what makes the
change live at runtime) and a wording caveat — `bash -c` reaches
pipes and redirection, so the tool-schema's "no command interpreter"
sentence is under admission pressure — carried in the harness's
`bl-292-t1-implementation-notes.md`, not resolved here.

**Docker remains the next same-shaped need and is not done** — C5
excluded it from this done-when and nothing admits it; that ticket
carries its own evidence when it is filed.

Row closed with `state: done`, `disposition: fixed`, the filed
done-when verbatim, moved to `docs/backlog-2026-06-closed.md` in
