# BL-291 — the worker and its Rust children open a visible console window on Windows

**Date filed:** 2026-10-06 · **Type:** missing capability — a
console-less worker start on native Windows · **Row:** BL-291 (open,
`docs/backlog-2026-06.md` §Harness) · **Design:**
`docs/aetheris/backlog/bl-291-windows-console.md` · **Citations:** `H` =
harness `aetheris` at `77cb0ab`.

---

## The finding

On native Windows (required by the operator — no WSL), starting a run
opens one or more visible Command Prompt windows:

1. **The Erlang side: the port to the worker.**
   `lib/aetheris/worker/client.ex:243@H` — `Port.open({:spawn_executable,
   worker_path}, port_options(sandbox_path))`; `port_options/2`
   (`:132-140@H`) is `[:binary, :exit_status, {:packet, 4}, {:cd, …}]`
   — **no `:hide`**. Erlang's `spawn_executable` on Windows opens a
   console for the child unless the port option `:hide` is passed; a
   hidden host process (the API server) therefore shows a visible
   Command Prompt for every started worker.
2. **The Rust side: the worker's own children.**
   `native/aetheris_worker/src/mcp.rs:24@H` — `std::process::Command::new(path)`
   for the stdio MCP servers, and the `python3` child at `:432@H` —
   **no `CREATE_NO_WINDOW` (`0x08000000`)** in the command's
   ` creation_flags`. On Windows a console subsystem child launched by a
   GUI/console process opens its own console window unless the flag is
   set.

So a Prepare turn on Windows flashes a Command Prompt per worker and per
Rust-spawned child on the operator's desktop. Nothing in the tree sets
either knob:

`git grep -n "\:hide" lib/aetheris/worker/client.ex` → 0 hits at `H`;
`git grep -n "CREATE_NO_WINDOW\|creation_flags" native/` → 0 hits at `H`.

## Design brief posture

`docs/aetheris/backlog/bl-291-windows-console.md` names both knobs —
**`:hide`** in `port_options/2` (per the port, Windows-relevant only)
and **`CREATE_NO_WINDOW`** via `creation_flags` on every
`std::process::Command` the worker spawns (`mcp.rs:24`, `:432`, and any
future child) — and **does not implement either**: the knobs are
T1's to place, and the done-when checks behaviour, not the lines.

## Reproduction

Live-first on Windows: any run that starts the worker, observed on the
desktop. The static proof is the two greps above plus the cited lines —
the port options list and the unsuffixed `Command::new` sites carry no
window-hiding knob anywhere in the chain.
