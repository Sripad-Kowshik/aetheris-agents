# BL-294 — run_command refuses curl, so an api agent cannot run the gate curls

**Date filed:** 2026-10-28 · **Type:** missing capability — `curl` as a
permitted `run_command` name · **Row:** BL-294 (open,
`docs/backlog-2026-06.md` §Harness) · **Design:**
`docs/aetheris/backlog/bl-294.md` · **Citations:** `H` = harness
`aetheris` at `f76d92a`.

---

## The finding

The exec server's `run_command` still cannot execute an HTTP call,
because the command name is matched against the hardcoded allowlist
that BL-292 and BL-293 widened by one name each — `bash`, then
`docker` — and no more:

- `native/aetheris_exec_server/src/runner.rs:33-54@H` —
  `PERMITTED_COMMANDS`, now 18 names: the original 16 plus `"bash"`
  (BL-292 T1) and `"docker"` (`:50@H`, BL-293 T1, each with its own
  in-const comment). `"curl"` appears nowhere in the const.
- `runner.rs:60-66@H` — `is_permitted/1` matches only the command's
  final path component against that const (unchanged across both
  admissions).
- The doc comment above it (`:57-59@H`) even uses curl as its
  **refused example**: "`../../bin/curl` → `curl` → not permitted".

A name not in the const is refused at dispatch:
`native/aetheris_exec_server/src/main.rs:444-459@H` —
`handle_run_command` returns `isError: true` with
`stderr: "command not permitted: {command}"` and `exit_code: -1` for
any command whose basename is absent from the const.

The refusal is pinned by a unit test:
`runner.rs:274-281@H` — `non_permitted_command_is_blocked` asserts
`!is_permitted("curl")` at `:276@H` (and `wget` at `:277@H`; the
BL-292 T1 comment records bash's removal from the same test). Unlike
BL-293's docker — never pinned refused — **curl is an asserted
refusal in two test sites**: `path_traversal_attempt_is_blocked`
(`:283-287@H`) asserts `!is_permitted("../../bin/curl")` and
`!is_permitted("/usr/bin/curl")` (`:285-286@H`) because curl itself
was the refused name the traversal pin was written against. Admitting
curl therefore touches three sites — the refusal test's curl line,
the traversal test's two curl assertions, and the doc-comment example
— none of which can be silently dropped, because each pins something
real (the refusal mechanism; the basename-resolution semantics; the
documented example).

Consequence: an agent that must run the **gate curls** — a `GET` or
`POST` with fixed arguments, the shape the api gate names for its
read/write checks — has no permitted way to invoke them. The step
cannot be inlined as some other permitted binary: the point of the
curl is the HTTP call it makes. This completes a pattern the series
has been naming one step ahead of the code: bash (BL-292), docker
(BL-293), now curl — each a name an existing gate agent needs, each
refused by the same const.

## Reproduction

No live run required — the refusal is static and unit-pinned:

- `grep -n '"curl"' native/aetheris_exec_server/src/runner.rs` → the
  hits are all negative assertions and the doc-comment example;
  `"curl"` is absent from `PERMITTED_COMMANDS` (`:33-54@H`).
- `cargo test -p aetheris_exec_server non_permitted_command_is_blocked`
  at `H` passes with curl refused by the same mechanism the test has
  always pinned.

## Closure record — 2026-10-28

**T1 landed in the harness: curl joins the permitted names.** The
harness commit, cited: `a2cdcbb` ("BL-294 T1: curl joins the
run_command permitted names").

- **Arm 1 — curl accepted.** `PERMITTED_COMMANDS` gains `"curl"`
  alone, placed after the BL-293 docker entry with its own BL-294
  comment; the const carries **19 names** at the commit (the T1
  message's "18" is a miscount in the message text, the same pattern
  as BL-293's — the diff shows the one addition and the file count is
  19). The three-site flip landed exactly as the brief's C2 spelled:
  `non_permitted_command_is_blocked` drops its `!is_permitted("curl")`
  line and wget now carries the refusal pin;
  `path_traversal_attempt_is_blocked` repoints both assertions from
  curl to wget (`../../bin/wget`, `/usr/bin/wget`) — the
  basename-semantics pin survives the admission instead of losing its
  subject, deleted by no one; and the doc-comment above
  `is_permitted` moves its refusal example to `../../bin/wget`, prose
  matched to the tests and the const. The positive arm gains the pin:
  `permitted_basename_is_allowed` asserts `is_permitted("curl")`
  beside the BL-292 bash and BL-293 docker pins.
- **Arm 2 — a fixed-args call returns the exit code.** No dispatch
  change was made or needed: the args vector passes through as given,
  and the new runtime pin drives the unchanged path —
  `run_curl_version_returns_the_existing_run_result` dispatches
  `run("curl", ["--version"], …)` and asserts the ordinary `RunResult`
  (exit code 0, stdout containing "curl"). The pin is network-free by
  design (`--version` is answered by the binary alone, verified live
  in the harness at curl 8.22.0) — the brief's STOP item resolved via
  its second named option, the BL-293 `--version` precedent.

C4 held in the same commit: wget stays refused direct, via
`../../bin/`, and via `/usr/bin/`; every absent name stays refused.
The harness commit also records the deliberate binary-rebuild side
effect (`priv/exec_server/aetheris_exec_server`, the standard compile
pipeline) and two carried items, not acted on: the capability caveat
(curl is a network client — nothing in T1 restricts its sub-command
surface or its egress; a curl-specific egress policy is a new decision
with its own brief, `bl-294-t1-implementation-notes.md` carries the
point), and the pin-carrier warning — wget is now the sole refused-name
subject in three tests plus the doc-comment, so if it is ever admitted,
all four sites need a new subject at once.

**No further name was filed** — C5 held: the const grows by curl only,
no successor admission accompanies this closure, and the next ask gets
its own row, evidence, and brief.

Row closed with `state: done`, `disposition: fixed`, the filed
done-when verbatim, moved to `docs/backlog-2026-06-closed.md` in
closure order (after BL-293). The implementation is a harness-repo
commit (`a2cdcbb`); nothing in `aetheris-agents` implements it.
