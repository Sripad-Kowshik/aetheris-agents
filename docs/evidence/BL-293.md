# BL-293 — run_command refuses docker, so a migrate agent cannot run the compose step

**Date filed:** 2026-10-28 · **Type:** missing capability — `docker` as a
permitted `run_command` name · **Row:** BL-293 (open,
`docs/backlog-2026-06.md` §Harness) · **Design:**
`docs/aetheris/backlog/bl-293.md` · **Citations:** `H` = harness
`aetheris` at `7476cfc`.

---

## The finding

The exec server's `run_command` still cannot execute a container
command, because the command name is matched against the hardcoded
allowlist that BL-292 widened by exactly one name — `bash` — and no
more:

- `native/aetheris_exec_server/src/runner.rs:33-52@H` —
  `PERMITTED_COMMANDS`, now 17 names: the original 16 plus `"bash"`
  after `"echo"`, under the BL-292 T1 comment (`:47-48@H`, "One name,
  nothing else"). `"docker"` appears nowhere in the const, and
  `grep -rn "docker" native/aetheris_exec_server/src/` returns **zero
  hits at `H`** — the exec server has no docker path at all.
- `runner.rs:58-64@H` — `is_permitted/1` matches only the command's
  final path component against that const (unchanged since before
  BL-292).

A name not in the const is refused at dispatch:
`native/aetheris_exec_server/src/main.rs:444-459@H` —
`handle_run_command` returns `isError: true` with
`stderr: "command not permitted: {command}"` and `exit_code: -1` for
any command whose basename is absent from the const.

The refusal is still pinned by a unit test:
`runner.rs:256-263@H` — `non_permitted_command_is_blocked` asserts
`!is_permitted("curl")` and `!is_permitted("wget")` (`:258-259@H`;
BL-292 T1 removed the `bash` line with a comment in place). The test
pins the refusal mechanism, not a name list — so admitting `docker`
needs the positive arm (a `docker` pin in
`permitted_basename_is_allowed`), not a flip of the refusal arm.

Consequence: an agent that must run a **compose step** — `docker
compose run --rm …` with fixed arguments, the shape a migrate gate
names for its container work — has no permitted way to invoke it. The
container step cannot be inlined as some other permitted binary: the
whole point of the step is that the migration repo's containers own
the work. BL-292's design brief named exactly this as the next
same-shaped need and excluded it from that done-when (BL-292 C5);
this row discharges the exclusion by filing it.

## Reproduction

No live run required — the refusal is static and unit-pinned:

- `grep -rn "docker" native/aetheris_exec_server/src/` → 0 hits at
  `H`; `"docker"` is absent from `PERMITTED_COMMANDS`
  (`:33-52@H`), whose only recent change is BL-292's `"bash"`.
- `cargo test -p aetheris_exec_server non_permitted_command_is_blocked`
  at `H` passes with docker refused by the same mechanism the test
  has always pinned.

## Closure record — 2026-10-28

**T1 landed in the harness: docker joins the permitted names.** The
harness commit, cited: `99aede4` ("BL-293 T1: docker joins the
run_command permitted names").

- **Arm 1 — docker accepted.** `PERMITTED_COMMANDS` gains `"docker"`
  alone, placed after the BL-292 bash entry with its own BL-293
  comment; the const carries **18 names** at the commit (the T1
  message's "17" is a miscount in the message text — the diff shows
  the one addition and the file count is 18). The positive pin lands
  beside the bash pin: `permitted_basename_is_allowed` asserts
  `is_permitted("docker")`. No refusal-arm flip, per the brief's C2 —
  `non_permitted_command_is_blocked` (curl, wget) is unchanged.
- **Arm 2 — a fixed-args call returns the exit code.** No dispatch
  change was made or needed: the args vector passes through as given,
  and the new runtime pin drives the unchanged path —
  `run_docker_version_returns_the_existing_run_result` dispatches
  `run("docker", ["--version"], …, 5_000)` and asserts the ordinary
  `RunResult` (exit code 0, stdout containing "Docker version"). The
  pin is daemon-free by design (`--version` is answered by the CLI
  binary alone, verified live in the harness at Docker 29.9.1), which
  is the brief's STOP item resolved the way its first option
  anticipated.

C4 held in the same commit: the refusal, path-traversal, and
absolute-path pins all pass untouched — every absent name stays
refused, including through the basename-resolving paths. The harness
commit also records the deliberate binary-rebuild side effect
(`priv/exec_server/aetheris_exec_server`, the standard compile
pipeline) and a capability caveat carried, not acted on: docker is a
container engine and the dispatching side imposes no argv filter, so
any confinement (daemon-socket denial, argv policy) is a new decision
with its own brief — `bl-293-t1-implementation-notes.md` carries the
point.

**No further name was filed** — C5 held: the const grows by docker
only, no successor admission accompanies this closure, and the next
ask gets its own row, evidence, and brief.

Row closed with `state: done`, `disposition: fixed`, the filed
done-when verbatim, moved to `docs/backlog-2026-06-closed.md` in
closure order (after BL-292). The implementation is a harness-repo
commit (`99aede4`); nothing in `aetheris-agents` implements it.
