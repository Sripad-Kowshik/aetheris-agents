# BL-285 — the runbook's HTTP API section never names `AETHERIS_AGENTS_ROOT`

**Date filed:** 2026-10-06 · **Type:** documentation · **Row:** BL-285
(open, `docs/backlog-2026-06.md` §Harness) · **Precedent followed:**
BL-276 (the runbook-update rule: the runbook owns the operational
surface, so a new endpoint's config surface lands there, not in a second
file) · **Citations:** `H` = harness `aetheris` at `8b1021e`.

---

## The finding

The harness runbook's HTTP sections — `## HTTP API server`
(`docs/aetheris/runbook.md:999@H`) and `## Playground API` (`:1028@H`) —
never mention `AETHERIS_AGENTS_ROOT`:

```bash
git -C ../aetheris grep -c "AETHERIS_AGENTS_ROOT" docs/aetheris/runbook.md
# → 0 (no match; exit 1)
```

But the variable is live configuration: BL-284's T1 route resolves
`agent_path` against it —

- `lib/aetheris/api/agent_file_run.ex:11@H` — the module doc: the path is
  resolved against the configured agents root (the `AETHERIS_AGENTS_ROOT`
  override, default `"agents"`) and must stay inside it;
- `config/runtime.exs:24@H` — `config :aetheris, :agents_root,
  System.get_env("AETHERIS_AGENTS_ROOT") || "agents"`;
- `docs/aetheris/playground-api.md:550,564@H` — §3.7 (`POST
  /api/playground/agent-file-runs`, BL-284 T1) documents the endpoint and
  the boot override with its default.

So the normative contract (playground-api.md §3.7) and the code both know
the variable; the operational runbook — the file BL-276 established as
the owner of playground endpoints' operational surface (its §Playground
API documents the token recipe, `api_bind`, the four stream config keys)
— does not. An operator following the runbook to start the server and
call the new route reads nothing about the one knob that decides which
file tree `agent_path` may resolve against, and nothing about the default
(`"agents"` — a path that only works if the server's cwd holds an
`agents` directory, which the agents checkout does not; an operator
pointing at `aetheris-agents/` must set the override, and the runbook
says so nowhere).

**The start that loads it is already documented:**
`docs/aetheris/runbook.md:1092@H` — `mix do app.config + aetheris server
--port 4001` (with the BL-275 trap named around it: bare `mix aetheris
server` does not evaluate `config/runtime.exs`, so the override would be
silently ignored on that start path). The missing piece is one line in
that existing section: the variable, its default, and that
`ct-bot/agents/main.exs` — the run BL-284's live check used — is
**relative to it**.

## Reproduction

Static, from the tree at `H` — the two greps above (count 0 in the
runbook; the three code/doc hits). No server run is needed: the finding
is a documented-file gap, provable by absence in a tracked file.

## Shape of the fix (T-ticket's; not done here)

One passage in the runbook's existing `## HTTP API server` / `##
Playground API` sections: the `AETHERIS_AGENTS_ROOT` override, its
default, that `agent_path` is relative to that root (with
`ct-bot/agents/main.exs` as the worked example), and the BL-275 coupling
— the override is read in `config/runtime.exs`, so it takes effect on the
`mix do app.config + aetheris server` start path, not bare `mix aetheris
server`. **No second runbook**: the fix edits the existing file only, and
this repo carries no runbook copy of it.
